# Metered capability API with documentation-led acquisition

## Mechanism

Some technical tasks are annoying in a specific way: everyone who needs them needs them repeatedly, doing them properly is tedious and brittle, and doing them badly fails silently. Teams build their own version, maintain it reluctantly, and would rather not.

Operate that one thing reliably, expose it as an interface, and charge per use.

## Why the distribution is the interesting part

No audience, no reputation, no outbound selling. A developer with the problem searches for it, finds documentation that solves it, and self-serves. `ev_028` credits an organic acquisition engine of SEO and content with taking the evidenced instance from roughly 7,000 dollars MRR to close to 1 million ARR in about fifteen months.

That channel compounds — accumulated documentation keeps ranking — and it selects for buyers who already know they have the problem, which removes the conversion difficulty every outreach-based candidate in this project has struggled with.

## The two obstacles, both serious

**Domain familiarity.** `ev_028` explicitly credits the founders picking an audience they already understood. Choosing the right annoying task is the entire bet, and a generalist choosing wrongly discovers it only after building. This founder is a generalist by constraint, which puts Gate 2 genuinely at risk for most instantiations of this family.

**Cost ordering.** Serving a request costs money. Free tiers and trials incur that cost before any conversion, which is the exact shape `ev_020` used to close the Atlassian Forge path — adoption generates cost while only conversion generates revenue.

A candidate in this family does not inherit a Gate 8 pass from the family record. It has to state how its own cost falls after payment, and a task with near-zero marginal cost, or prepaid credits with no free tier, are the only obvious routes.

## Requirements

Capital: depends entirely on the task. A task whose marginal cost is founder-owned tooling may be zero; a task requiring proxies, bandwidth or third-party API calls is not.

Expertise: high, and this is the binding constraint rather than a preference.

Network: none.

## Open questions

Whether a generalist can select the task correctly without the domain familiarity the evidenced instance's founders brought, or whether that familiarity is load-bearing rather than incidental.

What gross margin looks like after infrastructure cost at small scale, which decides whether the model works before volume or only after it.

How long the documentation-led channel takes to produce meaningful traffic from a standing start — the evidenced instance's fifteen-month acceleration followed years of prior work and an existing product, so it is not a clean answer.
